Agent Autoloop：让命令行 Agent 自己接活，只在拿不准时找你

这不是又一个 Agent 客户端。它是一台很小的自动中台：把「发生了一件事」变成「派给某个 Agent 干一轮」，干完收回执；需要你拍板时，才发一张卡片。

读法：先看 ①–③，能跑起来；④–⑥ 是每天会用的；⑦ 以后是扩展和改它。

01它是什么

一句话：事件进来 → 规则决定谁干、在哪干 → Agent 跑一轮就退出 → 结果写成回执；要问你时，发一张卡片。

它解决人不在电脑前，活就断了；Agent 要人守着终端。
它不解决不替你写业务、不做界面、不管模型质量。
它的成本一轮一轮花 token；规则写错会空跑。
它的边界只本机，不开公网端口；Agent 就是你已登录的 CLI。
先记住：它不是「定时任务 + 聊天」，而是「事件 + 规则 + 回执 + 卡片」四件套。少了回执，它就是一个 cron。

02心智模型

① 事件时间到了 / Webhook / 你点了卡片
② 规则交给谁 · 在哪个目录 · 什么 prompt
③ 一轮Agent 跑一次，进程退出
④ 回执 / 卡片结论落库；要你决定才发卡

六个词的关系是：事件归进事项，规则决定事项交给谁，跑成一轮，一轮的产物是回执；回执里可以请求你拍板，那就是卡片。

最重要的一条设计：一轮不等人。要问你时，这一轮直接结束，进程退出，不占内存、不烧 token；你回答后，它接着原来的会话继续。你三天不回，就三天没有 Agent 在跑。

035 分钟跑起来

用我们 fork 的隔离开发实例，不碰生产数据：

cd ~/Workspace/agent-autoloop
pnpm install                  # 本 fork 用 pnpm；pnpm-lock 从上游 package-lock 生成
./scripts/local-dev.sh        # 首次 init，然后前台启动；默认端口 3351

pnpm 10.x。上游的 package-lock.json 保留不动；pnpm import 负责生成 pnpm-lock.yaml。

另开一个终端：

export PATH="$HOME/.nvm/versions/node/v24.18.0/bin:$PATH"
export AGENT_AUTOLOOP_HOME="$HOME/.agent-autoloop-dev"

agent-autoloop status          # 谁在线、在跑什么、今天几轮
agent-autoloop try             # 用你的 Agent 走一遍「提问 → 退出 → 拍板 → 接着干」
为什么用隔离 home：生产实例是 ~/.agent-autoloop（端口 3350）。dev 用 ~/.agent-autoloop-dev（端口 3351），两边数据、密钥、规则完全分开。

看到 【等你决定】#1 试跑：选一个颜色，就说明整条链通了：Agent 干了一轮、问了问题、进程已退出。回答它：

agent-autoloop answer 1 2     # 选“绿色”
agent-autoloop why 1          # 看这一轮的完整时间线

04六个词

词是什么你要关心的
事件来源、编号、类型、对象、一句话、详情、链接。定时、Webhook、你的回答，都是事件。同一来源同一 id 只记一次，来源可以放心重发。
规则rules.json 里的一条：什么事件、交给哪个 Agent、在哪个目录、什么 prompt。规则才是指令；事件里的文字不能改路由。
事项同一条规则下同一个对象的事。卡片、复查、会话都挂在事项上。写了 parallel 才按对象拆；不写整条规则是一个事项。
一轮一次执行：领一批事件，交一份回执，结束。一轮会结束，事项会继续。
回执Agent 的最后一条消息。想让中台做的事都写在这里。结论 + 证据 + 落了哪个文件。
卡片给你看的东西。带选项 = 提问；不带 = 通知。回答后接着原会话干。

05三种日常

A · 定时任务（最简单）

{
  "name": "早报",
  "when": { "cron": "0 9 * * *" },
  "to": "codex",
  "cwd": "~/notes",
  "prompt": "整理昨天的笔记和提交，写今天的早报。"
}

保存后几秒内生效，agent-autoloop check 检查，rules explain 看下次什么时候跑。

B · 外部事件（Webhook / 轮询）

{
  "name": "处理 issue",
  "when": { "source": "github", "types": ["issues.opened"] },
  "to": "codex",
  "cwd": "~/code/app",
  "skill": "handle-issue",
  "parallel": 3
}

来源要先在 sources 登记；Webhook 验签密钥放 secrets.env，不进规则文件。
没有公网也能轮询：定时跑一段脚本，脚本在回执的 events 里交回新事件，id 稳定即可，中台负责去重。

C · 要你拍板

Agent 在最后一条回复里附一个 agent-autoloop 代码块：

订单核对完了，库存充足。

```agent-autoloop
{
  "ask": [{
    "title": "怎么发货？",
    "text": "两种方式今天都能发出。",
    "options": ["快递", "自提"],
    "key": "shipping"
  }]
}
```

中台发卡片、这轮结束。你答完，它用同一会话继续，不用重做前面的活。除了 ask，还能 notice（通知）、resolve（关掉旧卡）、later（约时间复查）、events（触发新事件）。

06规则怎么写

{
  "timezone": "Asia/Shanghai",
  "askFirst": ["删数据", "停服", "花钱", "对外发消息"],
  "agents": {
    "codex": { "use": "codex", "worker": "mac-mini" },
    "opencode": {
      "use": "command",
      "command": ["opencode", "run", "--format", "json", "{prompt}"]
    }
  },
  "rules": [{
    "name": "巡检",
    "when": { "cron": "0 8 * * *" },
    "to": "opencode",
    "cwd": "~/code/app",
    "prompt": "只读检查，结论放最后一条消息。",
    "parallel": 1,
    "resume": true,
    "tell": "needed"
  }]
}
字段作用
to用哪个 Agent（agents 里的名字）。
cwdAgent 在哪个目录干。静态，事件改不了——这是安全边界。
skill / prompt用哪份技能、给什么提示词。
parallel按对象分事项；每个对象一次一轮，最多几轮。
resume同一事项的新事件接着上一轮会话，默认开新会话。
tellalways / needed / never：什么时候给你发消息。
channels这张卡片只发到哪些通道。
安全边界：事件里带 cwd、agent、access 会被直接拒收。Issue 标题正文只作为资料放进文件，绝不拼进提示词。

07回执怎么写

不需要 SDK。约定只有一条：把结论写在最后一条消息里。要中台做事，就在末尾附代码块。写坏了，中台只让它重写最后一段，不重跑已经干完的业务。

结论：3 个查询掉出前 10，原因是 11-07 的合并重写。

证据：
- reports/gsc-1109.md
- 部署记录 11-07 14:20

```agent-autoloop
{
  "notice": [{"title": "归因完成", "text": "报告在 reports/gsc-1109.md"}],
  "later": [{"after": "2h", "reason": "复查排名是否恢复"}]
}
```

回执里的事件会继承 hops（跳数），超过 8 层只记录、不再派发，防止 Agent 之间无限对话。

08卡片怎么答

agent-autoloop status              # 看等你什么
agent-autoloop answer 3 1          # 第 3 张卡，选第 1 项
agent-autoloop answer 3 --text "都不对，走第三种"
agent-autoloop resolve 3 "已线下处理"   # 这张卡不用决定了

也可以走飞书/桌面通道点按钮。回答会变成一条新事件，叫醒提问的事项。

别忽略：卡片是异步的。你不答，它不占进程、不花钱，但事情就停在那儿——status 里会一直写着「等你」。

09插件四方向

方向内置你要加的时候
事件GitHub / GitLab / HTTP / 定时新系统怎么变成事件
AgentClaude Code / Codex / ACP / DSH / command新 CLI 怎么接（能收 prompt、打印最后一条回复就行）
通道桌面 / 飞书 / Webhook卡片发到哪、怎么回答
交付GitHub PR 流水线把 CI/CD 也做成插件

插件都是 plugins/<名字>/{agent,channel,source}.ts，由配置文件启用；内核不认识任何产品名。

10失败与重试

状态意思你做什么
queued排队；attempts > 0 表示失败等重试等，或看 why
claimed接单程序领走了，在跑等
unknown5 分钟没报，不确定还在不在跑看卡片 / 日志
done / nothing做成了 / 看过了没事可做无
cancelled连续 10 次失败、规则删除、或你手动停看 summary 里的原因

失败重试会合并同一事项后来的事件；回答和复查回到提问时的会话。接不上才开新会话——不会把做到一半的活重做一遍。

11CLI 速查

命令用途
up启动 hub + worker（前台）
status [--json]谁在线、等你什么、在跑什么、今天几轮

pause / resume暂停/恢复一条规则（不补跑）
emit <类型> --dry-run预演一条事件会派给谁
answer / resolve回答卡片 / 结案
key new <种类> <名字>新建来源/接单/通道/本人密钥
service install登录服务（常驻）
backup / restore备份与恢复

13学习路径

  1. 先跑 try：亲手走一遍「提问 → 退出 → 回答 → 接着干」，比读十页文档有用。
  2. 读 docs/protocol.md 的前两节：事件、规则、回执的字段就这些。
  3. 改一条自己的规则：定时跑一个只读脚本，让它给你发一张通知卡。
  4. 接一个外部来源：用 emit 手动发事件，确认路由对了，再接 Webhook。
  5. 写第一个插件：从 examples/plugins/hello-* 抄，先跑通再改。
  6. 看上游怎么改内核：git log --oneline upstream/main -- kernel/，读提交信息里的“为什么”。

14常见坑

  • cwd 是静态的。事件改不了目录；每个项目一条规则，或用 wrapper 自己切。
  • opencode 必须带 --dir。不带会把目标目录当 external_directory 直接拒掉（我们踩过）。
  • 事件正文不进 prompt。summary/detail 只是资料；要 Agent 读内容，让它读文件。
  • 桌面通道只在本机弹。人不在电脑前就看不到；远程要接飞书/钉钉/Slack。
  • 卡片不回答，活就停着。它不占进程，但也不会自己往前走。
  • 规则写错不会炸。旧规则继续跑，并推一张卡片告诉你错在哪——改完记得 check。
  • 别把生产数据放仓库。hub.db / config.json / secrets.env 都在 ~/.agent-autoloop。
